# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Static HTML, CSS, and JavaScript; GitHub Pages from `main` / `docs` (chosen for the small public demo).

## Users

People using Codex, Claude Code, Qwen Code, or another compatible agent to plan or deliver a project.

## Product Purpose

Project Flow guides a project from understanding and category selection through relevant research, feature decisions, UX/UI, delivery, and risk-sized validation. The demo should help visitors understand that path and preview it for a selected category and depth.

## Positioning

An agent-neutral, category-aware skill that scales work by scope and risk and uses only relevant tools that are available.

## Operating Context

The skill is installed from a public GitHub repository and used inside an AI coding or work agent. The demo is a static companion under `docs/`; it collects no user data and needs no server.

## Capabilities and Constraints

The workflow offers nine primary categories and three depth lanes: Quick, Standard, and High assurance. Current research, UX/UI guidance, specialized skills, and security checks are conditional on relevance and availability. Active security testing requires confirmed authorization and scope. GitHub Pages must be enabled for the repository's `main` branch and `/docs` folder.

## Brand Commitments

Use the name Project Flow. Keep the voice direct, natural, and evidence-led. Do not claim the workflow makes software impossible to compromise.

## Evidence on Hand

The source of truth is `skills/project-flow/SKILL.md` and its linked reference files. No user behavior analytics or performance claims are available; the demo must not invent them.

## Product Principles

- Understand the project before selecting a workflow.
- Keep small, low-risk work concise.
- Use current evidence when it could change a decision.
- Route only relevant skills and tools.
- Match validation depth to project risk and authorization.
